# 2026-10-22 — Google sign-in in the Android app never returned to the app

## Symptom

Inside the Android app (Capacitor WebView), tapping **Continue with Google**
opened the system browser. After signing in with Google there, the browser
stayed on the website — the app never came back and never showed a session.

## Root cause

Three independent gaps, all on the native side:

1. **Google refuses OAuth inside an embedded WebView.** The button called
   `authClient.signIn.social({ provider: "google", callbackURL: "/dashboard" })`,
   which redirects the WebView to `accounts.google.com`. Google hands that off
   to the system browser, so the OAuth round-trip happens outside the app.
2. **The callback URL pointed at the website.** `/dashboard` is relative, so it
   resolved to `https://remindly-pi.vercel.app/dashboard`. Better Auth set the
   session cookie in the *browser's* cookie jar and redirected the browser
   there.
3. **Nothing could bring the browser back.** `AndroidManifest.xml` only
   declared the `MAIN`/`LAUNCHER` intent filter — there was no custom URL
   scheme, no deep link, and no `@capacitor/app` / `@capacitor/browser`
   plugin. Even if the app had been reopened, the WebView's cookie jar is
   separate from the browser's, so the session cookie was unreachable.

Email + password login was never affected: it is a plain `fetch` from the
WebView, so the session cookie lands in the app's own jar.

## Fix

Use the platform **"Sign in with Google"** credential flow (Credential Manager)
and hand the resulting **ID token** to Better Auth, which already supports the
`idToken` variant of `POST /api/auth/sign-in/social`. The request is made from
the WebView, so the session cookie is set **in the app's own cookie jar** — no
browser hand-off, no deep link, no cookie transfer, and **no server change**.

The ID token has to be issued for the *web* OAuth client, because that is the
client id the server verifies the token against (`GOOGLE_CLIENT_ID`), so the
plugin is initialised with `webClientId`.

## Changes

| File | Change |
| --- | --- |
| `lib/auth/native-social-login.ts` | New. Lazy-loads `@capgo/capacitor-social-login`, initialises the Google provider with the web client id, runs the native credential flow and returns the ID token. Returns `null` on the web so callers fall back to the browser redirect. Distinguishes a dismissed account picker (`USER_CANCELLED`) from an app that is too old to ship the plugin (`UNIMPLEMENTED`). |
| `components/social-auth-button.tsx` | Google button now uses the native ID-token flow inside the app and falls back to the existing OAuth redirect on the web. |
| `package.json` / `package-lock.json` | Adds `@capgo/capacitor-social-login` (8.7.5, requires `@capacitor/core >= 8.0.0`). |
| `android/capacitor.settings.gradle` | Includes the plugin module (generated by `npx cap update android`). |
| `android/app/capacitor.build.gradle` | Adds the plugin dependency (generated by `npx cap update android`). |
| `.env.example` | Documents `NEXT_PUBLIC_GOOGLE_CLIENT_ID`. |
| `public/remindly-apk-release.apk` | Rebuilt release APK that ships the plugin (4 227 257 → 6 371 604 bytes, same signing certificate). |

`npx cap update android` was used instead of `cap sync` on purpose: `sync`
copies `public/` into the APK assets, and `public/` contains the published APK
itself, which would embed the old APK inside the new one.

## Setup that has to happen outside the repo

1. **Google Cloud Console** — create an **Android** OAuth client for the app:
   - package name: `com.ikalsama.remindly`
   - signing SHA-1: `FD:33:5D:17:B3:99:F9:0E:D4:6D:3A:2B:9A:5B:46:AF:68:4C:A5:C1`
     (release keystore `my-release-key.jks`, alias `keyRemindly`)
   - the **Web application** client id stays the `serverClientId`
     (`NEXT_PUBLIC_GOOGLE_CLIENT_ID`).
   Without it, Credential Manager rejects the sign-in attempt.
2. **Vercel** — add `NEXT_PUBLIC_GOOGLE_CLIENT_ID` (same value as
   `GOOGLE_CLIENT_ID`) to the project environment. This is a *web* variable:
   it is baked into the JS bundle the app loads, so it can be added later
   without rebuilding the APK.

## Verification

- `npx tsc --noEmit` → clean.
- `npm run lint` → 0 errors (50 warnings, all pre-existing; the extra ones come
  from the gitignored `android/app/build/intermediates/**/native-bridge.js`
  artifacts).
- `npm run build` → success.
- `POST https://remindly-pi.vercel.app/api/auth/sign-in/social` with
  `{"provider":"google","idToken":{"token":"not-a-jwt"}}` → `401` with
  `{"message":"Invalid token","code":"INVALID_TOKEN"}`, i.e. the request shape
  is accepted and the token is verified against Google's JWKS and the audience.
- Release APK rebuilt with `gradlew assembleRelease` (JDK 21): 6 371 604 bytes,
  `apksigner verify` passes with the same release certificate
  (SHA-1 `FD:33:5D:…:A5:C1`), and the dex contains
  `ee/forgr/capacitor/social/login/SocialLoginPlugin`,
  `com/google/android/libraries/identity/googleid/GetSignInWithGoogleOption`
  and `androidx/credentials/CredentialManager`. The published copy in
  `public/` is byte-identical to the build output
  (SHA-256 `4E1A09CB…40B43B`).
- End-to-end on a device still requires the Google Cloud Console step above,
  which cannot be done from this repository.

## Notes / not done
